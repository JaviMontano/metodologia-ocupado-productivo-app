Documento funcional independiente

De ocupado a productivo, convertido en una practica navegable.

Este documento define la mini app, sus reglas funcionales, el journey unico, la experiencia de taller, las capacidades Gemini BYOK y los criterios de terminado para entregar un repo estatico publicable en Hostinger. [DOC]

Disclaimer academico. Esta mini app es un material academico de MetodologIA. Opera sin login y guarda datos base solo en el navegador. El asistente Gemini es opcional y solo llama una API externa cuando el usuario pega su propio token. No es apta para produccion sin validacion legal, tecnica, regulatoria, de seguridad y de privacidad. [DOC]

01

Lectura ejecutiva

La app toma una semana de actividades y la convierte en un diagnostico accionable: que consume tiempo, que produce avance, que drena energia, que debe agruparse y que debe dejar de hacerse deliberadamente. [DOC]

Promesa funcional

El usuario abre index.html, captura actividades, recibe diagnostico, conversa con preguntas socraticas, disena su semana y exporta insumos BMAD/BMAP. [CONFIG]

Modelo de operacion

El core funciona sin login, sin backend y sin internet. Gemini solo se activa si el usuario pega un API token propio desde pantalla. [CONFIG]

Resultado del taller

El estudiante sale con evidencia local, un plan semanal y un handoff que puede alimentar BMAD, Antigravity, Codex o un pipeline de desarrollo. [DOC]

02

Usuario unico y contexto

El unico usuario funcional es una persona que quiere diagnosticar su uso del tiempo. Puede ser estudiante, profesional, emprendedor, facilitador o participante de workshop, pero esas son facetas de uso, no roles con permisos distintos. [DOC]

DimensionDefinicionImplicacion en producto
NecesidadEntender si su semana esta llena de movimiento o de avance. [DOC]La app debe convertir actividades en senales simples y accionables. [CONFIG]
Momento de usoWorkshop, clase, retrospectiva personal o cierre semanal. [SUPUESTO]Debe abrir rapido, sin crear cuenta ni preparar entorno. [CONFIG]
RiesgoEl usuario puede pegar informacion personal sensible. [INFERENCIA]Debe explicar privacidad local, permitir limpieza visible y no exportar secretos. [CONFIG]
Salida esperadaDiagnostico, preguntas, plan, Markdown y JSON. [DOC]Los outputs deben ser legibles por humanos y reutilizables por agentes. [CONFIG]
03

Journey funcional lineal

El journey no depende de login ni de aprobaciones externas. El asistente Gemini enriquece la experiencia, pero la ruta base debe completarse sin token. [CONFIG]

  1. Abrir. La persona abre index.html localmente o desde Hostinger y ve el disclaimer academico. [CONFIG]
  2. Capturar. Ingresa o pega actividades de una semana, con horas, impacto, energia, tipo de trabajo e interrupciones. [CONFIG]
  3. Diagnosticar. La app calcula indice productivo, riesgo de rueda de hamster, deuda de foco, energia neta y carga operativa. [CONFIG]
  4. Debatir. El usuario responde preguntas socraticas para pasar de explicacion a decision. [DOC]
  5. Planificar. Define prioridad unica, bloques de deep work, batch operativo, buffer y no deliberado. [DOC]
  6. Activar IA opcional. En workshop-bmad.html, pega token Gemini, carga anexos y conversa con el facilitador BMAD. [CONFIG]
  7. Exportar. Descarga Markdown y JSON para BMAD/BMAP sin incluir token ni secretos. [CONFIG]
  8. Reiniciar. Limpia sesion y token visible si quiere empezar de cero o preparar otra clase. [CONFIG]

06

Asistente Gemini BYOK y multimodal

El asistente se comporta como facilitador BMAD y mentor del workshop. Se activa solo cuando el usuario pega un token de Google AI Studio en pantalla. Google documenta que una key explicita puede usarse en web para REST, pero tambien advierte que una key real no debe exponerse en cliente para produccion; por eso esta implementacion es academica y BYOK. [DOC]

CapacidadComportamiento esperadoLimite funcional
Token en pantallaInput password, estado visible, guardar en sesion por defecto y recordar solo por opt-in. [CONFIG]No se commitea, no se exporta, no se comparte en handoff. [CONFIG]
Texto y MarkdownSe envian como partes de texto truncadas de forma defensiva. [CONFIG]Archivos enormes pueden degradar por contexto. [INFERENCIA]
PDFSe envia como inline_data application/pdf para analisis de documento. [DOC]Produccion deberia evaluar Files API, tamano y privacidad. [DOC]
ImagenSe envia como inline_data image/png, image/jpeg o image/webp. [DOC]No hace identificacion de personas ni inferencias sensibles. [SUPUESTO]
Function callingEl modelo puede pedir tools locales para leer diagnostico, clasificar anexos o generar handoff. [DOC]Solo se ejecutan funciones allowlisted en JavaScript local. [CONFIG]

10

Riesgos, limites y terminado

Riesgo de privacidad

El usuario puede cargar anexos con datos personales. La mitigacion es disclaimer, BYOK, ejecucion local, limpieza visible y no exportar token. [INFERENCIA]

Riesgo de produccion

Google recomienda no usar API keys reales en cliente para produccion; una version productiva requiere backend o secretos server-side. [DOC]

Definition of Done

La entrega queda lista cuando docs, workshop, specs, tests y trazabilidad reflejan app estatica, Gemini opcional, multimodalidad y function calling. [CONFIG]

MetodologIA

Documento academico ficticio. No sustituye validacion profesional, legal, tecnica, regulatoria, de seguridad ni de privacidad.

Hostinger ready

Sube este repo completo como archivos estaticos. La app base no requiere build, backend, login ni base de datos.
